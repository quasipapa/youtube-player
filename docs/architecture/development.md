# Development architecture

## Source and generated artifacts

Source artifacts:

- `src/`
- `includes/`
- plugin bootstrap
- `assets/js/editor-preview-controller.js`

Generated artifacts:

- `build/`, generated by `wp-scripts`
- compiled translation catalogs, generated from the English sources and German
  PO catalog

Never edit generated assets to make a source change.

PHP owns:

- registration
- authenticated editor endpoints
- parsing shared with server rendering
- dynamic markup

JavaScript owns:

- editor interaction
- per-instance browser state

SCSS owns plugin presentation.

Unit, WordPress/browser and manual test layers exercise the same observable
contract.

## Delivery architecture

```mermaid
sequenceDiagram
    actor Contributor
    actor Maintainer
    participant Repo as GitHub repository
    participant CI as CI workflow
    participant BuildJob as Build + version job
    participant PHPJob as PHP matrix job
    participant JSJob as JavaScript + CSS job
    participant WPJob as WordPress job
    participant ArtifactJob as CI artifact job
    participant Release as Release workflow
    participant Build as Generated build/
    participant Stage as Allowlisted staging tree
    participant Package as ZIP + SHA-256
    participant GitHubOutput as GitHub artifact / release

    alt Pull request or push to main
        Contributor->>Repo: Push commit
        Repo->>CI: Trigger workflow
        par Build and version
            CI->>BuildJob: npm ci + Composer install + npm run check
            BuildJob->>Build: Compile production assets
        and PHP matrix
            CI->>PHPJob: Composer install + configured PHP matrix
        and JavaScript and CSS
            CI->>JSJob: npm ci + JS/CSS unit and lint checks
        and WordPress integration
            CI->>WPJob: npm run test:local
        end
        BuildJob-->>ArtifactJob: Success
        PHPJob-->>ArtifactJob: Success
        JSJob-->>ArtifactJob: Success
        WPJob-->>ArtifactJob: Success
        ArtifactJob->>Build: npm run build
        ArtifactJob->>Stage: Copy runtime allowlist
        Stage->>Package: Create CI ZIP and checksum
        ArtifactJob->>GitHubOutput: Upload for 3 days
    else Push of an approved v* tag
        Maintainer->>Repo: Push release tag
        Repo->>Release: Trigger workflow
        Release->>Release: npm ci + npm run test:local
        Release->>Release: Verify tag and version agreement
        Release->>Build: npm run plugin:zip compiles assets
        Build->>Stage: Copy runtime allowlist
        Stage->>Package: Deterministic ZIP + checksum
        Release->>Package: Verify checksum and contents
        Release->>GitHubOutput: Publish release notes, ZIP and checksum
    end
```

`package-lock.json` and `composer.lock` pin the dependency graphs. Local and CI
quality gates install from those locks.

The CI artifact is short-lived and available only after all independent jobs
pass. A tag build repeats the complete gate. It then verifies version agreement
and publishes the deterministic release package.

| Generated artifact | Producer | Consumer or lifetime |
| --- | --- | --- |
| `build/` | `wp-scripts build` | Runtime allowlist for both package variants |
| Compiled translation catalogs | i18n generation in the quality gate | Committed/runtime language files |
| `yt-playlist-player-ci.zip` and checksum | CI artifact job | Review installation; retained for three days |
| `dist/yt-playlist-player.zip` and checksum | `scripts/build-zip.sh` | Release verification and GitHub Release |
| GitHub Release notes | Tag workflow | Immutable release record |
